1. MVP‑plan basert på stacken
Mål: En første versjon som beviser konseptet:

én sosial hub, 2) én konkurransemodus, 3) enkel UGC‑editor.

Scope MVP:

Kjernefunksjoner

Brukerprofil: registrering, avatar, enkel profilside.

Sosial hub: én 3D‑lobby (NordicHub light) i Three.js.

Konkurransespill: én parkour‑/obstacle‑bane med tidtaking og leaderboard.

Leaderboard: global + venneliste‑basert.

Enkel UGC‑editor v0: plassere blokker/objekter i 3D og lagre “baner”.

Foreldre‑modus v0: info‑side + enkel innloggingskontroll (aldersgrupper).

Teknisk MVP‑stack

Frontend: Next.js, React, Tailwind.

3D: Three.js (WebGL først, WebGPU senere).

Realtime: WebSockets (Node) for posisjon + timer.

Backend: Node.js (API + realtime), Supabase (auth, DB, realtime events).

DB: Supabase PostgreSQL (users, maps, scores).

Storage: Supabase storage / R2 (assets).

AI v0: kun moderering (tekstfilter) + litt assistanse i editor (f.eks. “fyll inn hull”).

2. Arkitekturdiagram (beskrevet i tekst)
Tenk dette som lag:

Klientlag

Next.js‑app: dashboard, profil, foreldre‑panel, marketplace (senere).

Spillklient i nettleser: React + Three.js for hub + parkour‑bane + editor.

API‑lag

Node.js API:

Auth‑proxy mot Supabase.

Endepunkter: /profiles, /maps, /scores, /leaderboard, /friends.

Realtime server (Node + WebSockets / Colyseus):

Håndterer posisjoner, start/stopp av runder, synkronisering.

Data‑lag

Supabase PostgreSQL:

users, profiles, maps, runs, scores, friendships.

Supabase Realtime:

Events for nye scores, nye maps, online status.

Storage (Supabase / R2):

3D‑assets, textures, avatar‑elementer.

AI‑lag (egen microservice, Python)

Moderering av chat (tekst).

Enkle forslag i editor (“symmetri”, “auto‑plasser hindringer”).

Admin/foreldre

Eget Next.js‑område med rollebasert tilgang (parent/admin).

4. Prototype‑plan for UGC‑editoren
Mål: En web‑basert editor der en 11–16‑åring kan lage en enkel parkour‑bane og spille den.

Fase 1: “Block Builder v0”
Teknisk

React‑komponent med Three.js‑scene.

Kamera: enkel orbit‑kontroll.

Verktøy:

Velg blokk‑type (plattform, vegg, hinder).

Klikk i scenen → plasser blokk på grid.

Slett/flytt blokk.

Lagre:

Eksporter scenen som JSON (blocks: [{x,y,z,type}]).

Lagre i Supabase maps‑tabell.

UX

Minimalistisk, få valg.

“Bygg → Test → Lagre”.

Fase 2: “Play Your Map”
Last inn map‑JSON i spillklienten.

Spilleren spawner på startpunkt.

Timer starter ved første bevegelse.

Når mål nås → score lagres.

Fase 3: “Share & Compete”
Liste over maps laget av brukeren.

“Spill vennens bane”.

Leaderboard per map.

Fase 4: AI‑assistent v1
Tekstfelt: “Gjør banen vanskeligere / lettere”.

AI foreslår endringer i JSON (flere hindringer, lengre løype).

Bruker kan godkjenne/avvise.
